## PHẦN 1: TỔNG QUAN VÀ MỤC TIÊU ĐỀ TÀI

### 1. Vấn đề thực tiễn & Điểm khác biệt
*   **Vấn đề:** Các hệ thống Drone/Robot truyền thống dùng WiFi hình sao (Star Topology) bắt buộc phải kết nối qua một cục Router trung tâm. Nếu xa Router hoặc Router hỏng, toàn bộ hệ thống tê liệt. Đòi hỏi phải có mạng 4G/SIM, nhưng ở vùng thảm họa/hầm mỏ thì không có sóng.
*   **Giải pháp (Mesh Network):** Thiết lập mạng Ad-hoc phi tập trung bằng ESP32. Các thiết bị tự động kết nối, tự chuyển tiếp sóng (multi-hop) cho nhau.
*   **Điểm mạnh:** KHÔNG cần SIM điện thoại, KHÔNG cần Internet. Bản thân các vi điều khiển tự tạo ra một mạng LAN vô tuyến riêng biệt. Đề tài thuộc mức độ **Khá - Khó (Top Tier)** do giải quyết bài toán định tuyến đa chặng và phân mảnh dữ liệu.

### 2. Tiêu chí đánh giá của Hội đồng (Metrics)
Hội đồng Điện tử Viễn thông không chấm điểm cơ khí (máy bay bay mượt hay không), mà chấm điểm chất lượng mạng vô tuyến:
1.  **Throughput (Băng thông):** Tốc độ truyền ảnh (byte/s) suy giảm ra sao khi đi qua 2 hop, 3 hop.
2.  **Latency (Độ trễ):** Thời gian chênh lệch từ lúc gửi đến lúc nhận.
3.  **Self-healing (Tự phục hồi):** Thời gian mạng tự định tuyến lại khi một node trung gian bị ngắt nguồn hoặc di chuyển ra ngoài vùng phủ sóng.

## PHẦN 4: NGUYÊN LÝ HOẠT ĐỘNG VÀ KIẾN TRÚC MẠNG

### 1. Kiến trúc Tree Topology (Mạng dạng cây)
Dựa trên cường độ tín hiệu (RSSI), mạng tự bầu cử và phân vai:
*   **Root Node (Nút Gốc):** Chỉ có 1 node duy nhất, cắm trực tiếp vào máy tính qua cáp USB. Nơi gom toàn bộ dữ liệu.
*   **Parent Node (Nút Trung gian):** Nằm giữa, làm nhiệm vụ nhận dữ liệu của nút con và chuyển tiếp lên nút cha (Ví dụ: Robot).
*   **Leaf Node (Nút Lá):** Nằm rìa ngoài cùng, chỉ thu thập ảnh/dữ liệu và gửi đi (Ví dụ: Drone).

### 2. Thuật toán phân mảnh dữ liệu (Data Fragmentation)
Giới hạn truyền WiFi (MTU) không cho phép gửi nguyên cục ảnh 30KB. Phải chia nhỏ:
*   Mỗi mảnh (chunk) mang theo Header chứa: `frame_id` (ID ảnh), `chunk_id` (vị trí mảnh), `total_chunks` (tổng số mảnh).
*   Bên nhận (Root) cấp phát bộ đệm, hứng đủ các mảnh cùng `frame_id` rồi mới xuất ra.

## PHẦN 5: CÁC ĐOẠN CODE LÕI CỦA HỆ THỐNG

### 1. Thuật toán gửi ảnh (Trên ESP32-CAM)
```cpp
#define CHUNK_SIZE 1024

// Cấu trúc Header của mỗi mảnh dữ liệu
#pragma pack(push, 1)
typedef struct {
    uint16_t frame_id;    
    uint16_t chunk_id;    
    uint16_t total_chunks;
    uint16_t data_len;    
    uint8_t  payload[1024]; 
} ImageChunkPacket;
#pragma pack(pop)

void send_frame_over_mesh() {
    static uint16_t current_frame_id = 0;
    camera_fb_t *fb = esp_camera_fb_get(); // Chụp ảnh
    if (!fb) return;

    uint32_t total_len = fb->len;
    uint16_t total_chunks = (total_len + CHUNK_SIZE - 1) / CHUNK_SIZE;
    current_frame_id++;

    ImageChunkPacket packet;
    packet.frame_id = current_frame_id;
    packet.total_chunks = total_chunks;

    // Cắt và gửi
    for (uint16_t i = 0; i < total_chunks; i++) {
        uint32_t offset = i * CHUNK_SIZE;
        uint16_t bytes_to_send = (total_len - offset < CHUNK_SIZE) ? (total_len - offset) : CHUNK_SIZE;

        packet.chunk_id = i;
        packet.data_len = bytes_to_send;
        memcpy(packet.payload, fb->buf + offset, bytes_to_send);

        // Gửi qua mesh (tuỳ hàm của thư viện ESP-MESH / painlessMesh)
        size_t packet_size = 8 + bytes_to_send;
        // ... Lệnh gửi đi ...

        vTaskDelay(pdMS_TO_TICKS(5)); // Chống tràn bộ đệm vô tuyến
    }
    esp_camera_fb_return(fb); // Giải phóng RAM
}
